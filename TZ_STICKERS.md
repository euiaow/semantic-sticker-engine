# ТЗ — «Стикеры по словам» (emoji-оверлеи, привязанные к речи)

**Версия:** 1.0
**Дата:** 2026-07-21
**Формат работы:** автономный модуль на аутсорс. Исполнитель **не получает доступ к основному репозиторию**.
**Что сдаётся:** Python-пакет `sticker_engine/` + CLI-демо + ассеты + отчёт по подбору порогов.

---

## 0. TL;DR для исполнителя

Ты пишешь автономную Python-библиотеку, которая:

1. Берёт **пословный транскрипт** видео (`word_cues.json`: слово + start/end в секундах).
2. Локально, **без сети и без LLM**, решает — на каких словах уместен эмодзи и какой именно
   (семантический поиск по эмбеддингам, без обучения модели).
3. Решает **где** на кадре его нарисовать, не задев запретные зоны (лицо, субтитры, хедер, b-roll).
4. Отдаёт покадровый RGBA-оверлей через API `get_overlays(time_sec)` — его будет вызывать наш
   рендер-пайплайн.
5. В комплекте — CLI, который делает то же самое end-to-end: `mp4 + cues.json → mp4 со стикерами`
   (это демо и приёмочный стенд, в проде он не используется).

Всё, что тебе нужно, лежит в этой папке: скелет кода с сигнатурами, тестовые данные, приёмочные
тесты. **Тесты — это и есть приёмка.** `pytest` должен быть зелёным.

## 1. Продуктовый контекст

Мы автоматически нарезаем длинные видео (подкасты, интервью, выступления) на вертикальные клипы
1080×1920 для Reels/Shorts/TikTok. У клипа уже есть: выжженные субтитры с покадровой подсветкой
слов, опциональный хедер сверху, опциональные b-roll вставки, музыка.

Не хватает «живости», которая есть у ручного монтажа в CapCut: **эмодзи, вылетающий на ключевом
слове**. Сказал «миллион» — вылетел 💰. Сказал «страшно» — 😱.

### Как это НЕ должно выглядеть
- Эмодзи не привязан к субтитру, не вставляется внутрь строки текста, не ломает вёрстку.
- Не мультяшный поток стикеров на каждом слове. Клип на 40 секунд = **5-10 эмодзи**, не больше.
- Никогда поверх лица говорящего.
- Лучше вообще без стикера, чем нелепый стикер. См. §5.4 — приоритет точности над полнотой.

## 3. Контракт данных (жёсткий, менять нельзя)

Все типы объявлены в `sticker_engine/types.py`. Файл дан в скелете — **сигнатуры и имена полей
менять нельзя**, по ним пойдёт интеграция.

### 3.1 Система координат и времени
- Кадр: **1080×1920** по умолчанию, но код обязан работать с любым `output_w × output_h`
  (мы рендерим и 1080×1350, и 1080×1080). Все размеры считаются от `output_w`/`output_h`, никаких
  захардкоженных пикселей.
- Начало координат — **левый верхний угол**, ось Y вниз.
- Время — **секунды от начала клипа**, `float`. Не кадры, не миллисекунды.
- Цвет оверлея — **RGBA**, `np.uint8`, shape `(h, w, 4)`, alpha не премультиплицированная.
  (Наш пайплайн сам переведёт в BGR и сделает альфа-блендинг.)

### 3.2 Входные типы

```python
@dataclass(frozen=True)
class WordCue:
    start: float   # секунды от начала клипа
    end: float
    word: str      # одно слово как его выдал ASR, с пунктуацией: "миллион,"

@dataclass(frozen=True)
class Rect:
    x: int; y: int; w: int; h: int      # пиксели выходного кадра

@dataclass(frozen=True)
class ForbiddenZone:
    t_start: float          # окно активности зоны
    t_end: float
    rect: Rect
    kind: str               # 'face' | 'subtitle' | 'header' | 'broll' | 'endscreen' | 'custom'
```

Замечания по зонам:
- Зоны **уже приведены к координатам выходного кадра** — пересчёт не твоя забота.
- Зон может быть много и они меняются во времени (лицо ездит по кадру: типично 2 сэмпла в секунду).
- `kind == 'broll'` и `kind == 'endscreen'` — особые: в эти окна стикеры **не показываются вообще**,
  даже если есть свободное место (см. §7.1).

### 3.3 Выходные типы

```python
@dataclass(frozen=True)
class StickerEvent:      # что показать и когда — результат §5-§6
    t_anchor: float          # старт слова-триггера, секунды
    t_start: float           # когда стикер начинает появляться
    t_end: float             # когда полностью исчез
    emoji: str               # сам символ, напр. "💰"
    asset_path: str          # абсолютный путь к PNG
    trigger_word: str        # слово-триггер как в транскрипте
    trigger_word_index: int  # индекс в исходном списке word_cues
    phrase: str              # окно контекста, по которому матчили
    score: float             # 0..1, уверенность матчера
    category: str = ""       # категория каталога — по ней работает фильтр §5.3

@dataclass(frozen=True)
class PlacedSticker:     # + позиция — результат §7
    event: StickerEvent
    x: int; y: int           # левый верхний угол при scale == 1.0
    size: int                # сторона квадрата в пикселях при scale == 1.0
```

Помимо полей у типов есть служебные свойства и методы — они тоже часть контракта и заданы
в `types.py`: `Rect.intersects(other, padding)`, `StickerEvent.duration`, `PlacedSticker.rect`,
`StickerConfig.total_duration`, `StickerConfig.sticker_size(output_w)`,
`StickerConfig.frame_margin(output_w)`, `StickerConfig.zone_padding(output_w)`,
`StickerConfig.from_json(path)`, константа `EXCLUSIVE_ZONE_KINDS`.

**Приоритет источников истины:** при расхождении этого документа с `skeleton/sticker_engine/types.py`
верным считается `types.py`, вторым — приёмочные тесты, третьим — текст ТЗ. О любом найденном
расхождении сообщать заказчику.

### 3.4 Публичный API (то, что вызывает наш код)

```python
# sticker_engine/__init__.py
def plan_stickers(
    word_cues: Sequence[WordCue],
    *,
    duration_sec: float,
    output_w: int,
    output_h: int,
    forbidden_zones: Sequence[ForbiddenZone] = (),
    config: StickerConfig | None = None,
    matcher: Matcher | None = None,     # для тестов/подмены; None => дефолтный эмбеддинг-матчер
) -> list[PlacedSticker]: ...

class StickerRenderer:
    def __init__(self, placed: Sequence[PlacedSticker], output_w: int, output_h: int,
                 config: StickerConfig | None = None) -> None: ...

    def get_overlays(self, time_sec: float) -> list[tuple[np.ndarray, int, int]]:
        """RGBA-оверлеи, активные в этот момент: [(rgba, x, y), ...]. Пустой список — норма."""
```

Разделение `plan_stickers` / `StickerRenderer` обязательно: планирование выполняется **один раз**
на клип, рендерер дёргается **на каждом кадре** (до 3000 раз) и обязан быть быстрым (§11).

### 3.5 Конфиг

```python
@dataclass
class StickerConfig:
    # плотность
    max_per_clip: int = 10
    density_per_min: float = 12.0
    min_gap_sec: float = 2.5          # минимум между стартами двух стикеров
    max_concurrent: int = 1           # одновременно на экране

    # качество подбора
    min_score: float = 0.45           # ПОДБИРАЕТСЯ ИСПОЛНИТЕЛЕМ, см. §13
    min_margin_over_runner_up: float = 0.03   # отрыв от второго кандидата
    phrase_window: int = 5            # слов контекста С КАЖДОЙ стороны (итого <= 11 слов)
    same_emoji_cooldown_sec: float = 15.0
    same_emoji_max_per_clip: int = 2
    edge_padding_head_sec: float = 1.0
    edge_padding_tail_sec: float = 1.5
    blocked_categories: tuple[str, ...] = (
        'weapons', 'violence', 'religion', 'flags', 'adult', 'medical', 'politics',
    )

    # геометрия
    size_frac: float = 0.13           # сторона стикера = size_frac * output_w  (1080 → 140px)
    margin_frac: float = 0.04         # отступ от краёв кадра
    zone_padding_frac: float = 0.015  # «воздух» вокруг запретных зон

    # анимация (секунды)
    pop_in_sec: float = 0.15
    hold_sec: float = 1.20
    fade_out_sec: float = 0.20
    pop_overshoot: float = 1.18       # пик масштаба на pop-in

    # инфраструктура
    assets_dir: Path | None = None    # None => <пакет>/assets/stickers
    catalog_path: Path | None = None  # None => <пакет>/assets/emoji_catalog.json
    model_name: str = 'sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2'
    model_cache_dir: Path | None = None
    seed: int = 0                     # детерминизм размещения
```

## 4. Ассеты: каталог эмодзи

### 4.1 Картинки
- Источник — **Twemoji** (github.com/twitter/twemoji), лицензия графики **CC-BY 4.0**.
  В сдаче обязателен файл `assets/stickers/ATTRIBUTION.md` с текстом атрибуции.
- Формат: **PNG 512×512, RGBA, с прозрачностью**, имя файла — codepoint в нижнем регистре:
  `1f4b0.png` (💰), `1f525.png` (🔥). Составные — через дефис: `1f468-200d-1f4bb.png`.
- Twemoji отдаёт SVG — рендерим в PNG 512 (cairosvg / rsvg-convert), никакого апскейла из 72×72.
- Объём набора: **150-250 эмодзи**. Не весь Unicode. Только те, что реально уместны в деловом /
  мотивационном / лайфстайл-контенте на русском.

### 4.2 Каталог `assets/emoji_catalog.json`

```json
[
  {
    "emoji": "💰",
    "file": "1f4b0.png",
    "category": "money",
    "ru": "деньги, миллион, прибыль, доход, заработок, богатство, выручка, капитал",
    "en": "money, million, profit, income, earnings, wealth, revenue"
  },
  {
    "emoji": "🔥",
    "category": "hype",
    "file": "1f525.png",
    "ru": "огонь, круто, мощно, взрыв, хит, топ, ажиотаж",
    "en": "fire, hot, awesome, viral, hype"
  }
]
```

Правила:
- `ru` — **основное поле для матчинга**, 5-15 слов/словосочетаний естественным языком. Не теги через
  подчёркивание, а живые слова — эмбеддинг-модель работает лучше с ними.
- `category` — из закрытого списка, включая «опасные» категории из `blocked_categories`.
  Опасные эмодзи **можно и нужно** держать в каталоге — фильтруются по категории на этапе подбора,
  чтобы конфиг решал, а не набор ассетов.
- Образец на 25 записей — `fixtures/emoji_catalog.sample.json`. Стилю следовать.
- Валидация: у каждой записи PNG существует, `emoji` уникален, `category` из списка. Есть тест.
- **Обязательный минимум:** итоговый `assets/emoji_catalog.json` должен содержать как минимум все
  25 записей из образца — в частности 💰 📈 😱 💡 ⏰ 🔥, их использует стаб-матчер в приёмочных
  тестах, и без них `test_returns_placed_stickers` не пройдёт. Простейший путь — взять образец
  за основу и дописать до 150+.
- **Запрещённые категории тоже нужны в каталоге**: минимум по одной записи на каждую из
  `blocked_categories` (`weapons`, `violence`, `religion`, `flags`, `adult`, `medical`, `politics`) —
 
 
### 4.3 Предрасчёт эмбеддингов
- Скрипт `scripts/build_catalog_embeddings.py` считает эмбеддинги `ru`-описаний один раз и кладёт
  в `assets/catalog_embeddings.npy` (+ `catalog_embeddings.meta.json` c именем модели, версией
  каталога, размерностью).
- **Рантайм не пересчитывает каталог.** На старте грузит `.npy`; если файл отсутствует или мета не
  совпала с `config.model_name` — считает на лету и пишет предупреждение в лог.

## 5. Подбор эмодзи (матчер)

### 5.1 Модель
- `sentence-transformers`, дефолт `paraphrase-multilingual-MiniLM-L12-v2` (мультиязычная, русский
  держит, ~470 МБ, CPU-инференс).
- **Никакого обучения, никакого дообучения.** Только косинусная близость к предрасчитанным
  эмбеддингам каталога.
- **Никакой сети в рантайме.** Модель должна подтягиваться из локального кэша
  (`config.model_cache_dir`, дефолт — переменная окружения `HF_HOME`). Скрипт
  `scripts/prefetch_model.py` кладёт её в кэш заранее.
- Модель грузится **лениво и один раз на процесс** (модуль-левел кэш). Повторный `plan_stickers` в
  том же процессе не должен грузить её снова.

### 5.2 Что именно матчим
Матчим **не отдельное слово**, а окно контекста — иначе «убить время» → 🔪.

1. Транскрипт режется на фразы по паузам между словами (порог **0.35 c**) — как в наших b-roll.
2. Внутри фразы для каждого слова-кандидата берётся окно `±config.phrase_window` слов **с каждой
   стороны** (в пределах фразы), то есть максимум `2 * phrase_window + 1` слов — это
   `StickerEvent.phrase`. Слова склеиваются пробелом, в исходном виде.
3. Кандидатами считаются только **содержательные** слова: длина ≥ 4 символа, не в стоп-листе
   (`sticker_engine/stopwords.py`, дан в скелете — дополняй), не числительное. Числительным
   считается токен, который целиком состоит из цифр и пунктуации (`«2024»`, `«15%»`, `«3,5»`);
   словесные числительные («три», «первый») числительными **не** считаются и кандидатами быть могут.
4. Эмбеддится **окно**, ищется ближайшая запись каталога по косинусу.
5. `score` = косинусная близость, приведённая к 0..1.

### 5.3 Фильтры уровня матчера (все обязательны)
Работают внутри `EmbeddingMatcher.match`, то есть на уровне **одной фразы**, без знания клипа:

| Фильтр | Правило |
|---|---|
| Порог | `score < config.min_score` → вернуть `None` |
| Категории | `category in config.blocked_categories` → вернуть `None` (не «берём второй по списку» — именно отбрасываем момент) |
| Отрыв | если разница score между первым и вторым кандидатом меньше `config.min_margin_over_runner_up` (**0.03**) — момент неоднозначный, вернуть `None` |

Фильтры уровня клипа (повтор эмодзи, края клипа, интервалы, плотность) живут **в планировщике**,
см. §6 — матчер о клипе ничего не знает.

**Дублирование защиты (обязательно):** матчер может быть подменён извне (`plan_stickers(matcher=...)`),
поэтому планировщик **обязан продублировать** проверку порога `min_score` и `blocked_categories`
на результатах матчера, а не доверять им. Это проверяется тестами
`test_low_score_yields_nothing` и `test_blocked_category_never_emitted`.

### 5.4 Философия ошибок (решение заказчика, обжалованию не подлежит)
**Пропустить лучше, чем ошибиться.** Клип, на котором матчер не нашёл ни одного уверенного момента
и вернул пустой список — это нормальный, приемлемый результат. Клип с одним нелепым эмодзи —
брак. Все спорные решения по порогам трактуй в сторону строгости.

### 5.5 Seam для тестов
Матчер выделен в протокол — приёмочные тесты планировщика подменяют его стабом, чтобы не тянуть
модель:

```python
class Matcher(Protocol):
    def match(self, phrase: str) -> tuple[str, str, float] | None:
        """-> (emoji, category, score) либо None, если уверенного соответствия нет."""

    def match_batch(self, phrases: Sequence[str]) -> list[tuple[str, str, float] | None]:
        """Батчевый вариант. ОБА метода обязательны: планировщик вызывает match_batch."""
```

Оба метода обязательны. Планировщик вызывает **только `match_batch`** — пофразовые вызовы модели
слишком медленные. `EmbeddingMatcher.match` реализуется как `match_batch([phrase])[0]`.

## 6. Планировщик моментов

Вход: список кандидатов после §5. Выход: `list[StickerEvent]`, отсортированный по `t_start`.

Правила, все проверяются тестами:
1. `t_start = t_anchor` (слово начинает звучать — стикер начинает вылетать). Никакого опережения.
2. `t_end = t_start + pop_in_sec + hold_sec + fade_out_sec` (дефолт — 1.55 c).
3. Между `t_start` соседних событий — не меньше `config.min_gap_sec`.
4. Одновременно на экране не больше `config.max_concurrent` (дефолт 1) — при пересечении окон
   более слабое по `score` событие выбрасывается.
5. Итоговое количество ≤ `min(config.max_per_clip, ceil(duration_sec / 60 * config.density_per_min))`.
6. Отбор при переизбытке — **жадный по `score`**, не по порядку в транскрипте: сортируем по score
   убыв. (при равенстве — по `t_anchor` возр., для детерминизма), берём сверху, каждое следующее
   проверяем на конфликты (3)-(5).
7. **Повтор эмодзи:** один и тот же эмодзи не чаще `config.same_emoji_cooldown_sec` (15 c) и не
   более `config.same_emoji_max_per_clip` (2) раз на клип.
8. **Края клипа:** не ставим в первые `config.edge_padding_head_sec` (1.0 c) и последние
   `config.edge_padding_tail_sec` (1.5 c) секунды.
9. **Дублирование фильтров матчера:** отбрасываем всё, что вернулось со `score < config.min_score`
   или с категорией из `config.blocked_categories` (см. §5.3).
10. **Эксклюзивные зоны:** события, чьё окно пересекается с зоной `kind in ('broll', 'endscreen')`,
    удаляются целиком (`drop_events_in_exclusive_zones`). Вызывается из `plan_stickers` **между**
    `plan_events` и `place_events`.
11. **Детерминизм:** одинаковый вход → побайтово одинаковый выход. Никакого `random` без
    `config.seed`, никаких множеств с недетерминированным порядком обхода.

Порядок конвейера в `plan_stickers` фиксирован:
`build_phrases` → `matcher.match_batch` → `plan_events` → `drop_events_in_exclusive_zones` → `place_events`.

**Когда `matcher` передан извне** (`plan_stickers(matcher=...)`): ML-модель грузить **запрещено**
(иначе не уложиться в 2 c из §11), каталог грузить **нужно** — из него берётся `asset_path` по
эмодзи. Если эмодзи, вернувшегося от матчера, нет в каталоге — событие отбрасывается с DEBUG-логом.

## 7. Размещение (решатель позиции)

Сторона стикера `size = round(config.size_frac * output_w)` (1080 → 140 px).

### 7.1 Жёсткие запреты
- Прямоугольник стикера, расширенный на `zone_padding_frac * output_w`, **не пересекается** ни с
  одной `ForbiddenZone`, активной в окне `[t_start, t_end]` события.
  «Активной» = `zone.t_start < event.t_end and zone.t_end > event.t_start`.
- Стикер целиком внутри кадра с отступом `margin_frac * output_w` от краёв.
- Если в окне события активна зона `kind in ('broll', 'endscreen')` — **событие удаляется целиком**,
  не переносится. (В эти моменты кадр занят другой графикой.)
- Если свободного места не нашлось — **событие удаляется**. Не сжимаем, не двигаем во времени.
  Удаление — штатный исход, залогировать на уровне DEBUG.
- **Два подряд идущих стикера не могут стоять в одной клетке сетки.** Это жёсткое правило, а не
  предпочтение: клетка предыдущего размещённого стикера исключается из кандидатов. Если после
  исключения кандидатов не осталось — запрет снимается (лучше повтор позиции, чем потерянный
  стикер), и это логируется на DEBUG.

### 7.2 Мягкие предпочтения (влияют на выбор из допустимых позиций)
Позиция выбирается по сетке-кандидатам (сетка `GRID_COLS × GRID_ROWS` = 6×10, можно плотнее)
с оценкой:
1. **Дальше от лица** — максимизируй расстояние до ближайшей зоны `kind == 'face'`. Расстояние
   нормируется на диагональ кадра, то есть слагаемое всегда в `[0, 1]`. **Если зон `face` в окне
   события нет — слагаемое равно 1.0** (никакая позиция не хуже другой по этому критерию).
2. **Верхняя половина кадра предпочтительнее** нижней (низ занят субтитрами и их стеком).
3. Ближе к центральной трети по X, чем к самым краям.

Все слагаемые нормируются в `[0, 1]` перед взвешиванием — иначе веса несравнимы. Веса подбираешь
сам, но они должны быть **именованными константами модуля** (`W_*`), а не магическими числами
внутри цикла — мы будем их крутить.

## 8. Анимация

Одна анимация на всё, без вариантов (решение заказчика). Функции — **чистые**, тестируются без
кадров:

```python
def scale_at(elapsed: float, config: StickerConfig) -> float
def alpha_at(elapsed: float, config: StickerConfig) -> float   # 0.0..1.0
```

где `elapsed = time_sec - event.t_start`.

| Фаза | Интервал | Масштаб | Альфа |
|---|---|---|---|
| pop-in | `[0, pop_in_sec)` | 0 → `pop_overshoot` → 1.0, пружинный ease-out-back | 0 → 1 линейно за первые 40% фазы |
| hold | `[pop_in_sec, pop_in_sec + hold_sec)` | 1.0 | 1.0 |
| fade-out | `[..., + fade_out_sec)` | 1.0 → 0.92 | 1 → 0 (ease-in) |
| вне окна | | — | 0 (оверлей не отдаётся вовсе) |

Кривая pop-in задана **обязательной формулой** (не «примером»): менять её нельзя, порог
непрерывности в тестах подобран именно под неё — с другой пружиной или другим `pop_in_sec`
тесты упадут. Пик равен ровно `config.pop_overshoot`:

```python
C1, C3 = 1.70158, 2.70158                     # C3 = C1 + 1
p = elapsed / pop_in_sec                      # 0..1
raw = 1 + C3 * (p - 1) ** 3 + C1 * (p - 1) ** 2   # классический easeOutBack: raw(0)=0, raw(1)=1
# растягиваем ТОЛЬКО превышение над 1.0 — иначе начало кривой уедет в минус
k = (pop_overshoot - 1.0) / (RAW_PEAK - 1.0)  # RAW_PEAK = max(raw) ≈ 1.0999
scale = raw if raw <= 1.0 else 1.0 + (raw - 1.0) * k
```

Итог: `scale(0) = 0`, `scale(pop_in_sec) = 1.0`, пик ровно `pop_overshoot`, разрывов нет.
(Проверено прогоном: с этой формулой все тесты `test_animation.py` зелёные.)

Требования к чистым функциям (есть тесты):
- `alpha_at(t) == 0.0` при `t <= 0` и при `t >= полная длительность`.
- `scale_at` достигает максимума ровно `pop_overshoot` внутри pop-in и возвращается к 1.0 ± 0.01
  к его концу.
- Обе **непрерывны**: при шаге дискретизации 0.001 c соседние значения отличаются не более
  чем на 0.05 — на границах фаз разрывов быть не должно.
  (Ограничения «не больше X за кадр при 30 fps» **нет** и быть не может: 0 → 1 за 0.15 c это
  ~4 кадра, скачок в четверть шкалы на кадр здесь физически неизбежен и это нормально.)
- Монотонны внутри hold и fade-out; на pop-in допустим ровно один локальный максимум (овершут).
- **Масштабирование идёт от центра стикера**: центр `(x + size/2, y + size/2)` не смещается при
  изменении scale. Это видно глазом, если сделать неправильно.

## 9. Рендерер

```python
class StickerRenderer:
    def __init__(self, placed, output_w, output_h, config=None): ...
    def get_overlays(self, time_sec: float) -> list[tuple[np.ndarray, int, int]]: ...
```

- Возвращает список активных оверлеев. Обычно 0 или 1 элемент.
- Каждый элемент: `(rgba, x, y)`, где `rgba.shape == (h, w, 4)`, `dtype == np.uint8`,
  `x, y` — координаты **левого верхнего угла уже отмасштабированного** спрайта, полностью внутри
  кадра (нам не нужно клипать — но мы всё равно клипаем, а вот выйти за границы ты не должен).
- Альфа уже перемножена на `alpha_at` (то есть канал A = `sprite_alpha * alpha_at`).
- **Предрендер обязателен**: в `__init__` PNG грузятся, ресайзятся и кэшируются.
  **Квантуются оба параметра** — и масштаб, и альфа, обе с шагом `SCALE_QUANT = 0.02`
  (`renderer.py`). Ключ кэша — `(индекс_события, quant(scale), quant(alpha))`. Тогда весь показ
  одного стикера укладывается в ~50 закэшированных битмапов, а `get_overlays` становится
  словарным лукапом без единой аллокации.
  Допуск теста на альфу — `± 0.06`, шаг 0.02 в него укладывается с запасом.
- Никакого дискового I/O и никаких аллокаций больших массивов внутри `get_overlays`.
- Ресайз — только качественный (`PIL.Image.LANCZOS` или `cv2.INTER_AREA` при уменьшении).
  Артефактов на альфа-канале быть не должно (проверяется тестом на «ореол»).

## 13. Отчёт по подбору порогов (обязательный артефакт)

`REPORT.md` в сдаче. Дефолт `min_score = 0.45` в конфиге — **заглушка**, реальное значение
подбираешь ты и обосновываешь.

### 13.1 Eval-набор — `fixtures/eval_set.json`
Файл создаёшь ты, он часть сдачи. Формат (заготовка на 29 фраз — `fixtures/eval_set.sample.json`):

```json
[
  {"phrase": "мы заработали первый миллион за три месяца", "expect": "💰"},
  {"phrase": "мы попали ровно в свою целевую аудиторию",   "expect": ["🎯", "👥", "🏆"]},
  {"phrase": "в общем я хочу сказать вам следующее",        "expect": null}
]
```

- `expect` — строка (единственный верный эмодзи), **список** (любой из них считается попаданием —
  используй, когда несколько эмодзи одинаково уместны) или `null` (стикер ставить не надо).
- Объём: **≥120 фраз, из них ≥40 негативных** (абстрактная речь, вводные, связки).
  Источник — `fixtures/word_cues.sample.json`, реальные субтитры русского YouTube, свои примеры.
- Тест `test_precision_and_recall` считает попаданием совпадение со строкой либо вхождение в список.

### 13.2 Содержание `REPORT.md`
- Таблица precision / recall при `min_score` = 0.30 / 0.35 / 0.40 / 0.45 / 0.50 / 0.55 / 0.60.
- Выбранное значение и обоснование.
- **Планка приёмки: precision ≥ 0.90 при recall ≥ 0.35** — это hard gate, он зашит в
  `test_precision_and_recall` и приоритетен именно в таком порядке (см. §5.4).
  Если планка недостижима — **останавливаешься и пишешь заказчику ДО сдачи**, с цифрами и
  предложениями (другая модель, лемматизация, сужение каталога, расширение `expect`-списков).
  Планка и тест меняются только совместным решением. Молча сдавать «почти дотянул» нельзя.
- Отдельный список «показательных провалов» — фразы, где матчер уверенно ошибается. Это ценнее
  средних метрик.
- Замер: сколько занимает загрузка модели, `plan_stickers` на клипе 60 c, `get_overlays` —
  сверка с §11.

## 14. Как это встанет к нам (для понимания контекста, делать не надо)

Наш рендер — покадровый цикл, который уже накладывает субтитры, хедер и логотип спонсора одним
и тем же способом: получает RGBA-оверлей и альфа-блендит в кадр. Твой `get_overlays` встанет в
этот же цикл, ещё одним слоем. Поэтому:

- API рендерера **сознательно** сделан как «дай оверлей на момент времени» — это в точности форма,
  которую ждёт наш цикл.
- Поэтому же ты **не рендеришь видео** в прод-пути и не трогаешь ffmpeg — это наша сторона.
- Поэтому запретные зоны — вход, а не то, что ты вычисляешь: у нас уже есть трекинг лиц, вёрстка
  субтитров и расписание b-roll.
